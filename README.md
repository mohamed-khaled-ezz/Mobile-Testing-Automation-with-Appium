# Mobile Testing Automation with Appium

Java-based mobile test automation project using **Appium, Selenium WebDriver, TestNG, Maven, and Android Emulator**.

This project covers Android application testing, mobile gestures, physical-device testing, and Chrome browser automation.

---

## 📌 Project Overview

This project was created as part of a **Mobile Testing Automation Mini Task**.

It demonstrates how to configure an Appium environment and automate common mobile testing scenarios on Android devices.

## 🛠️ Technologies Used

- Java
- Appium Server
- Appium Java Client
- Selenium WebDriver
- TestNG
- Apache Maven
- Android Studio and Android Emulator
- Android SDK and ADB

## ⚙️ Environment Setup

### 1. Verify Java and Maven

Open PowerShell and run:

```powershell
java -version
mvn -version
```

Both commands should display the installed versions.

### 2. Verify Node.js and npm

```powershell
node -v
npm -v
```

### 3. Install Appium

```powershell
npm install -g appium
```

Verify the installation:

```powershell
appium -v
```

### 4. Install the Android Automation Driver

```powershell
appium driver install uiautomator2
```

Verify the installed drivers:

```powershell
appium driver list --installed
```

### 5. Configure Android SDK

Set the `ANDROID_HOME` environment variable to your Android SDK directory.

Example:

```text
C:\Users\<YOUR_USERNAME>\AppData\Local\Android\Sdk
```

Add these directories to your Windows `Path` environment variable:

```text
%ANDROID_HOME%\platform-tools
%ANDROID_HOME%\emulator
```

Verify ADB:

```powershell
adb version
adb devices
```

### 6. Verify the Appium Environment

Run the diagnostic tool if installed:

```powershell
appium-doctor --android
```

Review the output and resolve any missing requirements relevant to your setup.

> Some versions of `appium-doctor` are deprecated. A warning does not necessarily mean Appium itself cannot run.

### 7. Start Appium Server

```powershell
appium
```

Default server URL:

```text
http://127.0.0.1:4723/
```

If your Java configuration uses `/wd/hub`, start the server with the matching base path:

```powershell
appium --base-path /wd/hub
```

The server URL configured in your tests must match the server configuration.

## 📱 Configure the Android Emulator

1. Open Android Studio.
2. Open **Device Manager**.
3. Create or start an Android Virtual Device.
4. Wait for the Android home screen to appear.
5. Verify the connection:

```powershell
adb devices
```

Example output:

```text
List of devices attached
emulator-5554    device
```

For a physical device, enable Developer Options and USB Debugging, connect the device through USB, and accept the debugging authorization prompt.

## 🧪 Test Scenarios

### 1. Built-in Android Application

The test demonstrates how to:

- Configure Android automation capabilities.
- Launch a built-in Android application.
- Locate an element using a suitable locator.
- Wait for the element to become visible.
- Interact with the element.
- Verify the expected result.

### 2. APK Application Testing

The APK test demonstrates how to install and launch an Android application and interact with its interface.

Place the APK at the configured path:

```text
APK/app-debug.apk
```

The test must reference the correct APK path and use locators that exist in the application.

> **Important:** A generic `app-debug.apk` is not automatically the API Demos application. If a test targets API Demos, provide the correct API Demos APK and configure its actual package and activity.

### 3. Mobile Gesture Automation

| Gesture | Purpose |
|---|---|
| Tap | Taps a visible element and verifies the result. |
| Scroll | Scrolls through a screen or scrollable container. |
| Slide | Moves a slider or another supported control. |
| Drag and Drop | Drags an item to a target and verifies the result. |

Each gesture test should interact with a visible element and verify the resulting screen state, value, or element position.

### 4. Chrome Web Testing

The Chrome test demonstrates how to:

- Start Chrome on an Android device.
- Configure browser automation capabilities.
- Open a web URL.
- Locate a web element.
- Interact with the element.
- Verify the expected browser behavior.

Chrome testing requires a compatible ChromeDriver setup for the installed Chrome version. If a compatibility error occurs, configure an appropriate ChromeDriver or a supported Appium-managed download strategy.

## 🎯 Desired Capabilities

The following Java example illustrates Android configuration. Update the values to match your environment and application.

### Android Emulator Configuration

```java
UiAutomator2Options options = new UiAutomator2Options();

options.setPlatformName("Android");
options.setDeviceName("Android Emulator");
options.setUdid("emulator-5554");
options.setAutomationName("UiAutomator2");
```

### APK Configuration

```java
options.setApp(
    "D:\\sprints_module_task\\Demo\\APK\\app-debug.apk"
);
```

### Built-in Application Configuration

```java
options.setAppPackage("YOUR_APP_PACKAGE");
options.setAppActivity("YOUR_APP_ACTIVITY");
```

Replace the placeholders with the actual application package and launchable activity.

### Chrome Browser Configuration

```java
options.setBrowserName("Chrome");
```

Use the appropriate configuration for each test. Do not leave placeholder values in executable test code.

## 🔎 Element Locator Strategies

Appium supports different locator strategies for identifying elements.

### Locate by Resource ID

```java
driver.findElement(
    By.id("com.example.app:id/login_button")
);
```

### Locate by Accessibility ID

```java
driver.findElement(
    AppiumBy.accessibilityId("Login")
);
```

### Locate by XPath

```java
driver.findElement(
    By.xpath("//android.widget.Button[@text='Login']")
);
```

**Best practices:**

- Prefer stable resource IDs and Accessibility IDs.
- Use XPath when a more stable locator is unavailable.
- Avoid brittle XPath expressions based on element position.
- Inspect the actual application using Appium Inspector before selecting locators.

## 🛠️ Troubleshooting

### Appium Cannot Connect to the Device

Check the emulator and ADB connection:

```powershell
adb devices
```

Confirm that Appium Server is running and that the configured server URL is correct.

### No Such Element

- Confirm that the correct application and screen are open.
- Inspect the current screen using Appium Inspector.
- Verify the locator value.
- Add an explicit wait when necessary.

### APK File Not Found

Check whether the APK exists:

```powershell
Test-Path ".\APK\app-debug.apk"
```

If the test references another location, update the configuration or place the correct APK at the expected path.

### ChromeDriver Version Mismatch

Check the installed Chrome version and configure a compatible ChromeDriver. Do not assume a driver for another major version will work.

### Tests Fail During Setup

Review the first meaningful error in the Maven output and inspect the relevant report under `target/surefire-reports/`.

A setup failure may prevent the test from reaching its actual actions.
